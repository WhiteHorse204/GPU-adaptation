# 19号：原DocLayNet比赛498页补跑与独立核验

2026-09-05已重新下载官方比赛图片和GT，完成498页、9158框、11类全量推理。收尾检查直接从原ZIP读取GT和图片，并用独立pycocotools调用对49800条预测CPU复算；全部总体与逐类指标与原结果误差小于1e-12。未重跑GPU，未改动已经完成的run.py、status.json、metrics.json或预测。

本次AP和AR均舍入到与作者一致的三位小数，这是较强的数值吻合证据。作者[论文§4](https://arxiv.org/html/2409.00847v2#S4)明确引用本HF模型，并说在DocLayNet competition benchmark上取得mAP0.602、mAR0.743；**论文没有写明四域平均还是全部图像合并计算，也没有绑定checkpoint哈希或完整后处理参数**。因此可以记录“原比赛基准上双指标与论文报告精度吻合”，仍不认证未披露协议完全一致。

[模型卡](https://huggingface.co/Aryn/deformable-detr-DocLayNet)的57.1仍缺具体数据和协议来源。不能将旧普通DocLayNet test4999页AP74.42、新比赛498页pooled AP60.15及模型卡57.1直接作同口径差值。普通test/val此前未发现划分混用，比赛集补跑解决的是先前漏查另一套作者基准的问题。

## 为什么官方比赛四域排名分仍为空

[比赛官网](https://ds4sd.github.io/icdar23-doclaynet/task/)要求先按文档域评估再平均；官方域规模应为reports293、manuals114、patents48、others43。但已取得的两个官方ZIP均有以下实际情况：

- `coco.json`的498条images均没有doc_category。
- 两ZIP各自498份JSON辅助metadata全部doc_category="other"、collection="subset"；不是可用的四域分组。
- 官方HF数据加载脚本中的doc_category、collection等features及读取逻辑都已注释。README示例不能代替这498页真实域映射。
- 本次所有预测domain保留null，`per_domain={}`、`competition_AP=null`及`competition_AR100=null`均保留。没有按文件名、GT或预测表现猜四域。

四域要求来自比赛官方，不应反过来断言Aryn论文一定用了四域平均。上述pooled数值吻合与官方排名分尚不可恢复，两个结论可以同时成立。

## 数据、推理及冻结记录

- 全498页图片均与两个官方ZIP中的PNG字节一致，全部1025×1025，CRC、SHA256和完整解码通过；原GT的images、annotations、categories均逐项不变，只增加COCO info/licenses默认字段。
- 图像ID及文件名全部唯一；498条JSONL无缺漏、无重复，49800个bbox有限且宽高为正，11类label与模型config身份映射一致，JSONL与扁平predictions.json完全相同。
- 保留官方DETR原生未裁剪预测；1056个框有部分超出原图边界，仍是有限正面积框，未擅自裁剪或丢弃，按原生COCO bbox方式评分。
- 使用HF DeformableDetrImageProcessor，短边800／最长1333、RGB rescale1/255、mean0/std1；FP32、batch1、score_threshold=0、top_k=100、无NMS，COCO maxDets=[1,10,100]及IoU .50:.05:.95。
- checkpoint加载missing/unexpected/mismatched/error字段均为空。运行版本为torch2.5.1+cu121、transformers4.50.0、pycocotools2.0.8，详细版本及有效processor在结果目录。
- 实际全量调用耗时62.36秒，GPU共享环境下仅作运行记录，不作为控制变量齐全的硬件吞吐测试。
- 协议及run.py/prepare.py哈希在运行时已写入status；收尾时发现尚未复制source_snapshot，现在核对实际脚本SHA与status一致后补充归档。archive_note.json明确标注运行后核验快照，未伪称运行前已复制。
