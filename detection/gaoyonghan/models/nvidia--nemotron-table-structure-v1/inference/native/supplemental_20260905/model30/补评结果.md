## 已知协议对齐与保留差异

采用作者七类发布代码commit `76c1dcd166ebae50bd1cad5ed1bbf3417e2fcc7c`。验证预处理实际运行Albumentations1.4.18的`Compose([NoOp()], BboxParams(format='coco',label_fields=['category'],clip=True))`，不是自行模拟clip。

作者batch8路径：按Parquet行序，每8张一起交给image processor形成整批padding；去掉pixel_mask；FP32模型eval；阈值0.0；无额外NMS；processor输出默认top-k100。5544恰好形成693批，全部保留。

GT遵循作者路径：processor labels的归一化cxcywh转换成xyxy，再乘每图orig_size；Torchmetrics1.4.1只接收boxes/labels，面积由框计算。batch8的归一化坐标相对于整批padding画布，按作者方式还原后可能不同于物理原图像素坐标，pred与GT使用同一转换。各图保存orig_size、padded_input_shape、processor_target_size及batch_image_ids，不能把这些额外保存的作者评估坐标直接当成去padding后的可视化坐标。

Torchmetrics1.4.1执行COCO式AP（IoU0.50:0.95、101点召回、maxDets1/10/100），并用独立COCOeval复算。两者绝对AP误差为batch8 `1.413828720764343e-09`、batch1 `2.1460939247930355e-08`。

原requirements列Torch2.3.0/Transformers4.44.0；本次复用已核验Torch2.5.1+cu121/Transformers4.50.0。两个本轮结果间没有改变这些版本。模型卡未给出可直接核对的完整原始逐图预测/训练日志，不能把剩余分数差距单独归因于某一个版本。版本语义的进一步只读核查由主任务汇总。

batch1冻结status中的`prediction_limit=300`描述有效输出数不准确：300是模型num_queries，实际processor默认top-k100，因此两组都是554400条预测。勘误已单列`protocol_clarification_batch1.json`，未改冻结status；batch8的三个字段已分别准确记录。
