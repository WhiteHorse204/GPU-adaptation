# 尚未闭环任务与证据

范围为62个检测模型中原工作簿未标绿的25个唯一模型。这里记录仍缺完整任务指标的部分；已找到候选数据不等于已取得有效金标。普通框、实例掩码、分类、关键点和阅读顺序按各自任务评分。

## 8. Anzhc/Anzhcs_YOLOs

原模型卡说明训练/验证数据由作者及朋友自标且不公开。本轮本地21个权重全部通过10张普通COCO图片实际推理；证据在 `results/remaining25_private_probe/8.json`，这不是准确率评估。

| 模型卡任务 | 已处理/候选替代 | 剩余缺口 |
|---|---|---|
| 通用人脸框+掩码 | 新版单类face权重可考虑CelebAMask-HQ或LaPa人工脸部掩码 | 需实际下载、冻结脸部组件合并定义并完成评估；旧版两类不能自动把人脸性别当作已知标签 |
| ManFace / WomanFace框+掩码 | CelebAMask-HQ有人工分割；带属性版本需按作者说明取得属性 | 不能仅凭图片外观自行补性别金标；目前未取得可核验的任务域标签 |
| 眼睛框+掩码 | CelebAMask-HQ或LaPa人工眼部掩码 | 需处理左右眼实例、眼睫毛范围与插画/真人域差异 |
| 头+头发框+掩码 | 同上，可合并真实标注的脸部、耳部和头发 | 需冻结是否含颈部、饰品等定义；未以矩形充当掩码 |
| 身体部位框+掩码 | 原集私有 | 尚未取得定义一致、带适用授权的独立实例掩码 |
| 15档尺寸检测/分类 | 作者自定义15档尺度 | 未找到带相同分档规则与实例框的独立金标；其他数据的通用大小标签不能直接冒充此分类任务 |
| 无人机框+掩码 | Anti-UAV可提供实际无人机的框 | 权重实际是segment，只有框还缺mask；VisDrone标注的是无人机拍摄的车辆/行人，不是无人机目标，不能替代 |
| Anime Score十档分类 | 卡中定义为固定年龄窗口图片的人类评分十分位 | 需要来源评分、采样时间和分位分组依据；不能把任意“画质好坏”标签当作Top10…Top100 |
| 文字框+掩码 | 已接入OmniDocBench 1651页人工多边形，评估Inline text | 实际权重9类；普通文字只覆盖1类。其他类型无对应金标，不伪合并。此结果不能代表其他10个任务 |
| 漫画分镜框+掩码 | Manga109有漫画框；MS92/MangaSegmentation可进一步核查 | Manga109下载需申请，普通框不是实例掩码；自动生成分割不能当作独立人工金标 |

来源：[模型卡](https://huggingface.co/Anzhc/Anzhcs_YOLOs)、[CelebAMask-HQ原作者](https://github.com/switchablenorms/CelebAMask-HQ)、[LaPa](https://github.com/jd-opensource/lapa-dataset)、[Anti-UAV](https://github.com/ZhaoJ9014/Anti-UAV)、[Manga109](http://www.manga109.org/en/)。

## 31. erax-ai/EraX-NSFW-V1.0

[原模型卡](https://huggingface.co/erax-ai/EraX-NSFW-V1.0)明确为私有数据、五类目标框。本轮nano/small/medium三种权重均通过10图实际推理，记录在 `results/remaining25_private_probe/31.json`。缺少的是有适用授权和对应目标框的独立评估集。整图NSFW分类集不能计算这些目标的检测AP；只有普通负样本也不能产生完整任务指标。下一步需要取得合适的现成检测标注，或在有权使用的数据上组织独立人工框标注。

## 32. qualcomm/MediaPipe-Hand-Detection

已从模型卡固定v0.61.0链接取得hand detector、landmark detector ONNX及external data，完成真实图片推理。在COCO WholeBody完整5000图上保存手掌代理框AP、21点二维PCK/NME、左右手准确率。代理框由真实标注的腕/MCP/拇指根部点几何构造，并非数据集原生palm box。左右手有原标注；全部21点都有匹配计数。

缺口：COCO没有这些图像的三维手部金标。[FreiHAND原作者已公开3960图评估标注](https://lmb.informatik.uni-freiburg.de/resources/datasets/FreihandDataset.en.html)，因此不能继续写“数据未公开”。实际下载 `FreiHAND_pub_v2_eval.zip` 在本机curl五次连接超时、urllib再次超时。已固定其[官方评估代码](https://github.com/lmb-freiburg/freihand) commit `5ea4ab9763fea0eec988a52bfa563333cb16523f`。

已核查的HF镜像 `nalbikyungmoon/FreiHAND_pub_v2_evaluation@f8afdc1e087636cc3f262ddd1135b88acacbe3b2` 共3961个文件，仅3960张JPG和.gitattributes，不含XYZ/K评估标注。其他镜像字段检查另存获取记录。下一步是补取官方含标注包并核对关节顺序，使用官方对齐算法报告3D误差和漏检覆盖；不能只用镜像图片宣布三维任务完成。

## 35. qualcomm/MediaPipe-Face-Detection

已补face detector与468点face landmark两个ONNX，完成COCO WholeBody完整5000图推理。保存人脸AP和与原标注有对应关系的7个稀疏网格点诊断。468点输出及检测器6点都已实际生成。

缺口：COCO的68点和普通人体耳点不等于检测器所需耳屏点，也没有全部468点独立真值。目前7点指标只是已匹配鼻尖、嘴角、眼角的二维诊断。需寻找具有明确6点语义或可审计468点拓扑的独立标注集；不能运行MediaPipe给数据打标签后再用同一模型评分。

首次面部ROI旋转方向设置错误，已按官方FaceApp的“右眼→左眼”索引修复并重新跑5000图；旧 `remaining25_qualcomm_v1/face` 的关键点指标无效，正确结果在 `remaining25_qualcomm_v3/face`。手部采用腕→中指根部旋转，未受此问题影响。

补充数值审计：旧Qualcomm手部42个、面部3个低姿态分数预测含NaN，未进入原PCK评分。原因是原生像素量化令旋转关键点重合。v3保留检测框并记录landmark_failure，禁止生成非有限坐标；两项均重新执行完整5000图，最终以v3为准。
